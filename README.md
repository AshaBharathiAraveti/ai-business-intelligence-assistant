# Mini AI Business Intelligence Assistant

A lightweight AI-powered Business Intelligence application that allows users to ask natural-language questions about sales data. It combines Gemini intent classification, Python analytics, SQLite, FastAPI, and Streamlit.


## Features

- Imports sales records from CSV into SQLite.
- Cleans and validates input data, including dates and numeric fields.
- Calculates total revenue, highest-revenue product, revenue by region, and monthly revenue.
- Compares revenue between two specified months, including absolute and percentage change.
- Summarizes data quality issues.
- Accepts natural-language questions through a FastAPI endpoint.
- Uses Gemini for intent classification, with local fallback classification for supported questions.
- Executes predefined analytics functions rather than model-generated SQL.
- Provides a Streamlit dashboard for interactive analysis.
- Includes automated tests for analytics, API requests, unsupported questions, and invalid month inputs.


## Technology Stack

- **Language:** Python
- **Data processing:** Pandas
- **Database:** SQLite
- **Backend:** FastAPI, Uvicorn
- **AI integration:** Google Gemini API
- **Frontend:** Streamlit
- **Testing:** Pytest, FastAPI TestClient

## Setup

1. Create and activate a Python virtual environment.
2. Install the required packages:

   ```bash
   python -m pip install fastapi uvicorn pandas google-genai python-dotenv streamlit requests pytest httpx
   ```

3. Create a `.env` file in the project root:

   ```text
   GEMINI_API_KEY=your_api_key_here
   ```

4. Keep `.env` private and do not commit API keys to version control.

5. Initialize and import the CSV data:

   ```bash
   python database.py
   ```

## Running the Application

Open two terminals in the project directory.

**Terminal 1 — Backend API**

```bash
python -m uvicorn main:app --reload
```

API documentation: http://127.0.0.1:8000/docs

**Terminal 2 — Streamlit frontend**

```bash
python -m streamlit run app.py
```

Open the local URL printed by Streamlit, typically http://localhost:8501.

## Supported Questions

- Which region has the highest revenue?

- Are there any data quality issues?
- How did revenue change from 2026-01 to 2026-02?

## Revenue Calculation Policy

Revenue is calculated as:

`Quantity × Unit Price − Discount Amount`

Only transactions with `Completed` status and non-null quantity and unit price are included. Returned transactions are excluded. Zero-quantity transactions contribute zero revenue. Missing prices are preserved as null and excluded from revenue calculations.


## API Endpoints

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/` | API welcome message |
| GET | `/health` | Health status |
| GET | `/analytics/revenue` | Total revenue |
| GET | `/analytics/top-product` | Highest-revenue product |
| GET | `/analytics/regions` | Revenue by region |
| GET | `/analytics/monthly` | Monthly revenue |
| GET | `/analytics/data-quality` | Data quality summary |
| GET | `/analytics/revenue-change` | Compare revenue between two months |
| POST | `/ask` | Classify a natural-language question and return analytics |

### Example request

```json
{
  "question": "How did revenue change from 2026-01 to 2026-02?"
}
```

For revenue comparison questions, provide two months in `YYYY-MM` format.

The application maps recognized intents to predefined analytics functions. It does not execute SQL generated by the language model.

## Architecture

1. CSV sales data is loaded and cleaned using Pandas.
2. Valid records are stored in SQLite.
3. Streamlit sends user questions to the FastAPI backend.
4. Gemini classifies supported questions into predefined analytics intents when available.
5. Local fallback classification handles supported questions when Gemini is unavailable.
6. Python analytics functions execute predefined SQLite queries.
7. The API returns structured JSON for display in Streamlit.

## Security and Limitations

- API keys are stored in environment variables rather than hard-coded in source files.
- Model output is validated against an allowlist of supported intents.
- SQL is defined in trusted application code rather than generated and executed by the model.
- The application currently supports a fixed set of sales analytics questions.
